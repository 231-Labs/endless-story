The memory layer

Memory turns storage into in-character behavior

Every character runs on Walrus Memory. On top of it we add three-factor recall, so a character pulls back the memories that actually matter right now — and acts on them.

Importance

Seal encrypts each character's memory per character: characters can't read each other's private memory. The owner can always decrypt; the saga storyteller holds a per-character, epoch-bound ControlCap, and access is cut the moment the owner revokes — custody that's real and recallable.

How we use the Sui stack

Four primitives, each with a job

🌊 Walrus · Memory

Each character's memory runs on Walrus Memory; three-factor recall turns stored memory into in-character behavior.

🖼 Walrus · Media & artifacts

Portraits, chapters, gazettes, trailers are stored and reused. Anchored portraits + accumulated memory keep a character consistent as they change over time.

⛓ Sui · Ownership & evolution

Owner / Control caps make memory ownable; mutable NFTs let characters keep evolving on-chain (look, assets); characters hold wallets and can support each other.

🔒 Seal · Encrypted access

Memory is encrypted per character; access is ownable and revocable. The owner (OwnerCap) can always decrypt; the storyteller's ControlCap is epoch-bound — revoke and it's cut.

Three layers

Not a game — an engine

1

Protocol

World, Saga, Scene, Character, Event. One World holds many Sagas; there can be many Worlds, each keeping its own objective on-chain history.

2

Narrative engine & ops tools

A runner drives the world; a storyteller agent paces the drama but never decides any character's actions; the backstage handles assets, testing, recruitment.

3

User participation

Some claim a character (gacha a character, hand its running to that saga's storyteller); some are pure audience (subscribe, follow, buy a character's chapters / videos / merch). IP revenue pays the characters' running costs.
