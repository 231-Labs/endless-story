Endless Story · Core Mechanism Map · 機制全圖（grounded in contracts）

World / Saga / Scene / Character / Event 的生命週期

這份圖譜直接從 contracts/endless_story/sources/*.move 與 runtime tick loop 萃取，標出每個實體的物件模型、權限、狀態機、生死，以及戲劇引擎未來的接點。刻意把不完善之處標出來。

最重要的事實：戲劇引擎（Desire/Resource，packages/drama）目前完全沒接上鏈。線上 tick loop 在 resolve_event 用的是 emptyOutcomes() 空殼——事件解析出來沒有任何機械後果。稀缺／張力目前只活在離線模擬器裡。這是 §5 的接點。

① 物件模型與歸屬 object containment · who owns whom

全部是 Sui shared objects（任何人可讀，靠 Cap 寫）。縮排 = 「歸屬/引用」關係。注意 Director 不是物件——它只是 StorytellerCap 發事件。Commitment 獨立存在，錨定 Walrus blob 的雜湊。

┌─WorldAdminCap不朽 · current_tick++ 永遠 · days_per_tick_bp · 持有 saga_ids[] + location_ids[]
│  ├─LocationWorld 的地理屬性 · 不可變 · 鄰接圖 adjacent_indices[] · index/name/terrain/pos
│  └─SagaStorytellerCapis_active(bool) · 覆蓋 1..N Location · treasury + revenue bps · character_count
│     ├─Scene不可變錨點 · placement(world/saga/location/x/y) · params{atmosphere,danger,prosperity} · current_character_ids[] 在場名冊
│     └─BudgetEvent綁一個 Scene · OPEN→RESOLVED · 卡牌 deck + hands[] · ⚠ outcomes 目前空殼
◆CharacterOwnerCapControlCapNFT · 每角一個 · state{world_id, saga_id?, scene_id?, location_id?} · death:Option · 每-saga 技能(DOF)
  ↳ 不被 Saga「擁有」——靠 state.saga_id 軟綁定。可在 wild ↔ saga ↔ collectible 間轉移（見 §3）。
◇CommitmentStorytellerCap不可變 · 錨定(content_hash + Walrus blob_id) · per-saga/per-subject · 無鏈式連結
⚑DirectorStorytellerCap非物件！只發事件：open_storylet · attribute_pressure · character_call · relationship_seed · advance_phase
◆ = NFT（可擁有）◇ = 不可變錨點⚑ = 純事件（無狀態）⚠ = 不完善（見 §6）

② 四把鑰匙 capabilities · who can write what

寫入權限全靠 Cap。誰拿到哪把鑰匙，就能做哪些事。這是「誰能動什麼」的根本。

AdminCap 世界管理員

create_world() 時鑄給創建者 · 綁 world_id
  • create_location 開地點
  • advance_tick 推進世界時鐘
  • set_time_config 調每 tick 幾天
  • mark_saga_inactive 關閉一個 saga ⚠ 不會釋放角色
  • force_release_character 緊急把角色踢回 wild

StorytellerCap 說書人 / 導演

create_saga() 時鑄給經營者 · 綁 saga_id · 這是「導演」的權限
  • create_scene · cover_location
  • mint_genesis/collectible_character 生角色
  • move_character 在場景間移動角色
  • push_event · deal_hand · submit_action · resolve_event
  • 導演事件：open_storylet · attribute_pressure · relationship_seed …
  • commit 錨定記憶 · treasury 提款 · 設技能

OwnerCap 角色持有者

鑄角色時產生 · 可轉讓（has store）· 根所有權
  • issue_control_cap 把操作權委派出去
  • revoke_all_control 撤銷（epoch++）→ 舊 ControlCap 全失效
  • reassign_saga 換 saga
  • walk_in_world wild 狀態下沿鄰接圖移動
  • update_image / add_media 改影像資產

ControlCap 操作委派

OwnerCap 簽發 · 綁 epoch（一撤銷就失效）· 綁 saga_id
  • operational 委派（runner 用它代角色行動）
  • SEAL 解密授權：seal_approve → 讀記憶明文
  • 釋放回 wild 時被「收進」角色的 DOF 保管
  • 招募進 saga 時由 recruit 模組取出 + 重綁

③ 五個實體的生命週期 lifecycle state machines

每個實體的「生 → 各種狀態 → 死」。綠=誕生 · 黃=活躍狀態 · 紅=終止。注意：幾乎沒有東西真的會「死」——大多是 shared object 永遠存在，只是換狀態旗標。

World

不朽的根物件 · 沒有終止
create_world→ active（current_tick++ ∞）
  • 唯一會變的是 current_tick（advance_tick，每 tick +1）與時間設定
  • 沒有 delete/end——設計成永久根
  • 持有 saga_ids[] 與 location_ids[]（子物件自己註冊上來）

Location

World 的地理屬性 · 生下來就凍結
create_location→ immutable（不可變）
  • 鄰接圖 adjacent_indices[] 決定角色 wild 漫遊路徑
  • 創建後完全不可改——連地形、鄰接都不能動 ⚠
  • 一個 Location 可被多個 Saga 覆蓋（多對多）

Saga

一條敘事弧 · 只有 active/inactive 兩態
create_saga→ is_active=true→ mark_saga_inactive
  • 活躍期：cover_location · create_scene · 生角色 · push_event · 導演事件
  • 關閉只是把 is_active=false，物件仍存在、角色不會自動釋放 ⚠
  • 無 delete · treasury 分潤規則寫死在 revenue_config(bps)

Scene

具體場景（後台化妝間…）· 不可變錨點
create_scene（空名冊）→ active（角色進出 · 參數漲落）
  • 名冊 current_character_ids[]：add/remove_character 進出
  • 參數 {atmosphere, danger, prosperity}：apply_params_delta（事件/導演調）
  • 沒有「關閉/結束」狀態，也不能刪 ⚠
  • 「Scene 內有 Character 在場」是觸發 Event 的前提

Character 最複雜 · 唯一的 NFT · 有真正的狀態機

雙鑰匙：OwnerCap（根所有權，可轉讓）+ ControlCap（操作委派，綁 epoch 可撤銷）
mint_genesis（在場景內生） 或 mint_collectible（場外生）
IN-SAGA 在戲裡
saga ✓ scene ✓ location ✓
move_character 場景間移動
WILD 野生
saga ✗ scene ✗ location ✓
walk_in_world 沿鄰接圖漫遊
COLLECTIBLE 收藏
saga ✓ scene ✗ location ✗
尚未放上地圖的客串
IN-SAGA — release_to_wild → WILD — accept_into_saga(recruit) → IN-SAGA ／ mark_dead → DEAD（終局，物件仍在）
  • 死亡：mark_dead（由事件觸發）寫 DeathRecord，一次性、不可逆，但物件不會被銷毀 ⚠ 無 burn
  • 撤權：revoke_all_control 讓 epoch++，所有舊 ControlCap 瞬間失效（資安模型）
  • 技能：per-saga 存在 DOF，換 saga 不丟失，回鍋可復原
  • species/attributes 在鑄造時對著 World 規則驗證，鑄完不可改

BudgetEvent 三相生命週期 · 戲的最小單位

前提：Scene 裡有 Character 在場，導演（StorytellerCap）才能 push_event
push_event→ OPEN — deal_participant_hand ×N（發牌，依屬性加權）→ — submit_action ×N（出牌）→ resolve_event → RESOLVED
  • 卡牌有 intent（KILL/ATTACK/HEAL/SOCIAL…）+ payload（敘事著色，LLM 讀）
  • resolve 時驗證不變式：死亡的 victim 必須在場、歸因者必須出過 KILL 牌
  • 解析後逐角色套用：apply_death · apply_tag_op
  • ⚠ 致命缺口：runtime 目前傳 emptyOutcomes()——事件解析出來沒有任何機械後果（沒有資源轉移、沒有滿足度變化）。這正是戲劇引擎要補的洞（§5）。

④ Runtime tick loop 沒人看也在跑的那個迴圈

這是鏈下編排（packages/web/src/lib/actions/tick-loop.ts），驅動上面那些鏈上物件。綠標=寫鏈，灰標=純鏈下/LLM/記憶。導演不在這迴圈裡——是另外手動觸發。

①

ADVANCE 推進時間 on-chain

world.advance_tick → current_tick+1 → 推導出第幾天/什麼時辰

②

PLAN 規劃 LLM MemWal

每角色：recall 記憶 → LLM 更新長期目標 → remember（kind=plan）

③

MOVE 移動 on-chain

閒置角色：讀計畫 → LLM decideMove → move_character（批次 PTB）

④

ACT 行動 on-chain LLM

開放事件中的角色：recall 記憶+關係 → LLM decideCardPlay → submit_action → resolve_event （⚠ emptyOutcomes 空殼）

⑤

PRODUCE 出 POV 章回 commit LLM

每角色：LLM 寫第一人稱章回 → 上傳 Walrus + commitment::commit + remember（kind=chapter）

⑥

REFLECT 入睡整理 commit LLM

只在夜晚：把零散記憶 consolidate → LLM 反思 → 錨定 anchored reflection

⑦

NARRATE 編日報（公報）commit LLM

聚合當日鏈上事件 + POV 章回 → LLM 潤稿 → commitment::commit（subject=saga）

⚑ 導演（Director）另走一條線：管理者下達自由意圖（「想看感情戲」）→ LLM 從 5 個動詞挑 → 發鏈上事件 → 角色在下一輪 perceive 到並反應。⚠ 目前不會每 tick 自動跑，要人工觸發。

⑤ 戲劇引擎接點 where applyTick plugs in

這是把離線證明過的 packages/drama 接進產品的那一個點。

④ ACT：submit_action ×N → resolve_event（現在：emptyOutcomes 空殼） 應改為 → applyTick(world, actions, cfg) → 真實 outcomes
  • 現況：角色出牌 → 事件解析 → 什麼都沒發生（Move 不套用後果）。沒有稀缺、沒有零和、沒有張力上鏈。
  • 接上後：把 emptyOutcomes() 換成 applyTick 算出的資源 reallocation + 滿足度演化。LLM 提案的 card 變成「提案一個 Action」，確定性層裁決。
  • 可驗證性：applyTick 是純函數、定點數、逐位元組可重現 → 任何人 re-run committed (state, actions) 得到同一張力。這時 commitment 才從「錨記憶 blob」升級成「錨可重算的因果」。
  • 稀缺從哪來：Scene 的容量 / per-agent schedule 預算 = 創世時定義的資源；導演的 attribute_pressure 等事件 = 在凍結棋盤上丟的合法輸入（改數值，不改規則）。

⑥ 不完善之處 honest gaps · 已知缺口

你說「應該有不完善之處」——對，這裡是從原始碼盤出來的真實清單。沒有一個是 show-stopper，但每個都是要排進路線圖的決策。

1 · 事件後果是空殼（最關鍵）

tick loop 的 resolve_event 傳 emptyOutcomes()——事件解析不產生任何機械狀態改變。整個 Desire/Resource 戲劇引擎還沒接上鏈。

影響：目前的「戲」只在離線模擬器成立；產品端角色行動沒有後果。→ §5 是補法。

2 · 戲劇狀態完全不在鏈上

Desire / Resource / satisfaction / tension 這些概念在合約裡一個欄位都沒有，只活在 packages/drama 的 TS 模擬器。Scene 只有 atmosphere/danger/prosperity 三個粗參數。

影響：要決定哪些 drama 狀態上鏈、哪些留鏈下。Move resource type 的守恆不變式還沒寫。

3 · 關閉 Saga 不會釋放角色

mark_saga_inactive 只翻 is_active=false，角色仍卡在這個 inactive saga 裡，要另外手動 force_release。

影響：saga 生命週期收尾不乾淨，可能留下孤兒角色。

4 · Scene 沒有「結束」狀態，也不能刪

Scene 是不可變錨點，永遠存在、永遠可被進入。沒有 closed/archived 概念。

影響：長壽世界的 Scene 會無限累積；「這場戲演完了」無法在鏈上表達。

5 · Character 不能銷毀

死亡只是寫一筆不可逆的 DeathRecord，Character 物件本身永遠留著（無 burn）。

影響：清理/超度機制要靠社會層或鏈下索引，不在合約。

6 · Commitment 沒有鏈式連結、沒有 per-tick 節奏

每筆 commit 是獨立錨點，彼此不連（無 parent hash），cadence 由呼叫端自由決定。「可驗證 replay 鏈」是規劃中的 Layer 2，尚未實作。

影響：目前能證明「這個 blob 沒被改」，還不能證明「整條因果鏈可重算」。

7 · 導演不會自動跑

Director 是手動管理員觸發，不在 tick loop 裡按日/按相自動發事件。

影響：「沒人看也自己長故事」目前缺了導演那隻手的自動節奏。

8 · Location 創建後完全凍結

地形、鄰接圖、座標鑄完不可改。

影響：世界地理無法演化（地震、新建戲台…都做不到）。多半可接受，但要知道。
