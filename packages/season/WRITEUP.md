# 個體化記憶：從「角色能不能記住對話」到「一段經歷如何在不同人身上長成不同的人」

> 這份是 `packages/season` 的設計真相。它把一段設計討論落成一個**可跑、可重現、可證偽**的 harness。
> 讀碼順序：`README.md` → 本檔 → `src/*` → `driver/run.ts` 的 `out/`。

---

## 0. 命題的轉向

一般會問的是：**「角色能不能記住對話？」** 這題其實不難——存下向量、召回、餵回 prompt 就行（真實系統早已做到，見 `packages/web/src/lib/chain/memory.ts`）。

真正有研究價值、也最容易在多人生成敘事裡**坍縮**的，是另一題：

> **一段共同經歷，如何在不同角色身上留下不同的改變，並在未來造成可觀察的行為差異？**

多人對話會坍縮，是因為：所有角色看同一份完整 transcript、用相似的推理、都以「合作、回應話題」為默認目標、最後又讀同一份摘要——於是資訊、語氣、觀點、情緒全部同步，像一群輪流替作者解說劇情的人。

真實系統其實已經**刻意抵抗**這種坍縮：沒有共享 transcript、每個角色用自己的記憶＋人設**私自**推理、有全知防護欄（`situation-core.ts` 的 `assertPerceivable`）、私密記憶不強制統一 canon（`NARRATIVE_AGENTS.md` §5）。但它**沒有**一個把「一次交談 → 多份私人記憶 → 一段時間後的差異化行動」當成**可量測單元**來驗的東西。這個 harness 就是那個東西。

## 1. 雙向循環（人格不是等記憶蒸餾完才出現）

```
人格／關係 → 如何理解對話 → 記住什麼 → 如何重新解釋自己與對方
           → 人格／關係緩慢改變 → 下一次採取不同的行動
                     ↑___________________________________|
```

關鍵：**原本的人格，在蒸餾之前就已經在動作**。它先決定了

- 她**注意到**哪句話　（`perceive.ts`：salience 先過濾 transcript）
- 她把那句話理解為**體貼、敷衍、試探，還是羞辱**　（`perceive.ts`：valence）
- 她願不願意**相信**對方、把什麼**說出口**、什麼**藏起來**
- 事後**反覆想**的是哪一瞬間

所以 harness 把 PERCEIVE（注意＋定調）獨立在 DISTILL（蒸餾五層）**之前**。同一份客觀 transcript，先被三種人格讀成三種不同的「入心片段＋定調」，蒸餾才在那個已經帶偏的基礎上進行。

---

## 2. 五層記憶（只有第一層近乎事實）

蒸餾**不應**把三次事件粗暴寫成「柳生春深愛金鳳」。它該形成**可累積、可動搖的內在結構**。所以一場戲的私人記憶拆成五層（`types.ts` `PrivateSceneMemory`）：

| 層 | | 性質 |
|---|---|---|
| 1 | **經歷**　我看見／聽見／做了什麼 | 近乎事實（唯一） |
| 2 | **解釋**　我認為那代表什麼 | 允許偏見、誤解 |
| 3 | **關係更新**　我現在更信任／畏懼／虧欠／懷疑誰 | 主觀、可不對稱 |
| 4 | **自我敘事**　這件事證明我是怎樣的人 | 允許合理化、自欺 |
| 5 | **行為傾向**　下次類似情境我更可能怎麼做 | 可累積、可動搖 |

第 5 層不是結論，是**傾向**（`Disposition`）：如「親密時傾向用照顧代替承諾」「害怕被要求明確選擇」「越是被迴避越要抓個明白」。每場戲只**微調**其強度，且 `integrate.ts` 夾限——所以人格會**漂移**，不會因一場戲翻轉。第 3 層同理。這就是「自優化」：記憶不是被動堆疊，而是持續把自己整理成一個略有偏差、卻連貫的人。

再加一層**帳本**：一場戲可以留下日後可兌現的**承諾／怨懟／疑問／風險**（`LedgerItem`）。金鳳在查問那場埋下的「疑問」，正是她後來逼問時**兌現**的東西。

## 3. 最小研究單元，搬上台：《嫌隙》

三個角色（`fixtures/chunxue.ts`）：柳生春（坤生，被三角關係圍著）、蘇映雪（花旦，青梅竹馬的師姐）、**金鳳**（新增的刀馬旦，烈性、佔有慾強）。前兩位是 spring-snow preset 的正牌台柱；金鳳是為這個實驗新造的第三者。

樞紐一場（`s3`，即設計討論裡的例子）：**金鳳問柳生春「你昨夜又去師姐房裡了？」→ 生春頓了一頓 → 「去看看她，她嗓子不好。」** 客觀上只有一場談話，卻長出三份私人現實（`out/01_divergence.md`，deterministic 實跑）：

- **柳生春**：金鳳第一次明著查問我——我讀成**試探**，當時沒有否認（並替自己記下一筆「含糊過去，遲早要還」的風險）。
- **金鳳**：柳停頓了一瞬才回答——我把那個**停頓當成答案**（讀成**迴避**＝默認，懷疑一步跨過發作線，埋下一個「疑問」）。
- **蘇映雪**（`s4` 才風聞）：金鳳已經開始介意我——我讀成**威脅**，往後應當**避嫌**。

三份記憶互不知情、皆未外洩。真正推動後續劇情的，就是這三份現實之間的縫隙。

劇情季用兩種場景（`fixtures/season.ts`）：**scripted** 是受控刺激（同一份客觀台詞打向所有人，乾淨地驗差異化蒸餾）；**enacted** 是角色**依累積記憶行動**產生台詞（驗記憶真的改變了行為）。

## 4. 評估：不是「對話自不自然」，而是六個結構問題

全部 deterministic 實跑通過（`driver/report.ts`；`out/00_report.md`）：

| | 準則 | deterministic 結果 |
|---|---|---|
| **M1** | 同一事件 → 彼此不一致的記憶 | 多人場 5/6 出現 ≥2 種讀法；樞紐事件被讀成 試探／迴避／威脅 三版 |
| **M2** | 匿名行動 → 認得出是誰 | 5/5＝100%（隨機基準 33%）：逼問=金鳳、搪塞=柳生春、避嫌=蘇映雪 |
| **M3** | 過去經驗真的改變後續選擇（非台詞提及） | 有 s3 記憶：金鳳**逼問**；抽掉 s3 其餘全同：金鳳只**按兵**。因果成立 |
| **M4** | 保留誤解與認知落差 | 樞紐讀法歧異且**不被和解**（金鳳的確信不回落；映雪信柳、金鳳疑柳，兩極並存） |
| **M5** | 漸變、不因一場對話翻轉 | 任一場對任一關係軸的移動 ≤ 夾限 0.15；最大漂移 0.45 分 3 步累成 |
| **M6** | 留下日後可兌現的承諾／怨懟／疑問／風險 | 開 13 筆（風險6／疑問3／承諾2／怨懟2），兌現 2 筆（金鳳 s3 疑問→s5 逼問） |
| **INV** | 私密記憶不跨角色滲漏、無全知、夾限恆成立 | 全綠（測試 `test/invariants.test.ts` 強制） |

M3 是最乾淨的一刀：把樞紐那場**整場抽掉**再重跑（做法照抄 `packages/economy` 的 alliance on/off 消融），只有金鳳對柳生春的懷疑**沒跨過發作線**，她就從「逼問」變成「按兵」。行為的改變**可回溯到一段具體記憶**，而不是台詞裡順口提了一句。

## 5. 誠實的分界：mock 證什麼，真 LLM 證什麼

這條界線很重要，不能含糊：

- **deterministic（mock）模式證的是「機制」**：五層資料模型能承載差異、雙向迴圈接得通、六項指標與不變量成立、夾限保證漸變、私密不滲漏——而且**可重現、可進 CI**。它**不**證「LLM 會自發地產生差異化理解」。mock 的差異，是每個角色的 salience 先驗（`persona.primed`）**確定性地**把同一份中性 tag 讀出不同結果——這是「人格先於蒸餾動作」的一個**可驗證模型**，不是幻覺。
- **真 LLM 模式證的是「湧現」**：`perceive.ts` / `distill.ts` / `enact.ts` 的真模型路徑**忽略** `primed`，改從 `temperament` ＋累積狀態讓注意力與五層自己長出來。要驗「同一份 raw transcript 交給三種人格，模型會不會自發蒸餾出三份不同的私人現實」，就得帶 key 跑（`AI_PROVIDER=… node driver/run.ts`），再用同一套 `metrics.ts` 量。**這一步需要金鑰，尚未在無網環境跑過**——這是下一步，不是已完成的宣稱。

同一套骨架、同一套指標，兩種後端。這正是 `packages/troupe` 的紀律：mock＝結構與邏輯，真 LLM＝文采與湧現。

## 6. Port path：搬回真實 runner（gate-after）

這是 harness，不碰鏈。但五層每一層在真實系統都有落點——搬是逐層對接，不是重寫：

1. **五層 → MemWal kind**（`packages/web/src/lib/chain/memory-tags.ts` 的 `MemoryKind`）：
   - 經歷 → `observation`(i=4)／`chapter`(i=5)
   - 解釋 → `reflection`(i=7)，由 sleep 壓縮產生（`reflection-trigger/consolidate.ts`）
   - 關係更新 → `relationship`(i=8)，**但**保留主觀分支：目前 relationship-assess 寫的是**對稱共享** canon（唯一的例外層）；本 harness 的 `Stance` 是**每人各一份、可不對稱**的私自看法，對應該接進「主觀 relationship memory」那條，而非公開 tie。
   - 自我敘事 → `genesis`(i=7)／POV 燈下反思
   - 行為傾向 → `plan`(i=8)
   一場戲目前散寫成多個 blob；本模型的貢獻是把它們綁成**一場一份、分層**的記錄——搬回去就是在 `tick-phases` 的寫記憶處，多帶 valence／disposition-delta 的結構化 metadata。
2. **行為傾向 → 導演／角色的意圖推導**：`NARRATIVE_AGENTS.md` §8c「待續①」明寫——目前意圖是**行當靜態 ambition**，「記憶調變為下一層」。本 harness 的 `enact.decideMove`（累積 disposition／stance → 行動）就是那一層的**離線原型**：把它接進 `contest.ts` 的意圖項與 `character-agent` 的 decide，資源爭搶與發言就會**從記憶長出來**（如「金鳳因心底的懷疑而特別想逼柳生春表態」）。
3. **夾限漸變**：`integrate.ts` 的 per-scene clamp 對應「人格漸變」的產品保證——搬進寫記憶路徑即可，成本為零。
4. **不變量照搬**：私密不跨角色（呼應 SEAL 的 `char_<id>` namespace 與 `assertPerceivable`）、無全知、無強制 canon——這些在真實系統已是鐵則（§5），harness 只是把它們變成**會 fail 的測試**。

---

## 7. 明確不做 / 侷限

- 不宣稱 mock 的差異＝LLM 湧現（見 §5）。真 LLM 端的湧現驗證是**下一步**。
- salience 先驗（`primed`）是刻意的建模選擇，讓 deterministic 路徑可重現地分歧；它是「注意力被人格決定」的一個粗模型，不是人格的全部。
- 目前三人、六場、一條三角線。要驗更大 cast／多條張力線是否仍維持差異（會不會回到坍縮），是規模化的下一題。
- 沒有共享 canon 事實層——這是**刻意**的（§5）：想讓 A 真的知道 B 的秘密，得另走「導演種公開事實」機制，不可靠把別人的私密記憶餵進來。

---

_一句話：這裡研究的不再只是「怎麼叫 LLM 寫出有戲的台詞」，而是**人如何在彼此的記憶裡，逐漸成為不同的人**。精彩故事，是這條鏈成立後的外顯結果。_
