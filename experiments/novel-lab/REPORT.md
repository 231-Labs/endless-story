## 一、結論先講（TL;DR）

你的章回「像一段觀察、可有可無」，**不是單一 bug，是兩層各缺一塊、且互相掩蓋**：

1. **材料層**：餵給 POV 的材料**幾乎全是狀態快照**（我在哪、想要什麼、跟誰什麼關係、別人剛做了什麼），
   唯一的「劇情」是 `triggerNarrative` 那一句「開了一樁事」。而且 storylet 模式下**事件大多不結算**
   （EVENT_LIFECYCLE.md §1 的「鬼打牆」），所以連那一句也只有「開場」、沒有「轉折／結算／代價」。
   → **沒有劇情可推進，模型只能寫風景。**

2. **Prompt 層**：現況 prompt 為了壓制「LLM 亂編劇情／melodrama／身份漂移」，把規則寫成
   「**寫一個克制、可拍、不捏造、結在小鉤子的瞬間場面**」。它無法區分「捏造正典」（壞）和
   「在既有事件內把劇情推一步」（好），於是**把劇情一起禁掉了**。
   → **就算材料給了劇情，prompt 也會把它壓回觀察。**

3. **連續性層（書級）**：完全沒有「這是第幾回、上一回結在哪、本回要改變什麼、整本書在問什麼」的概念。
   合本 prompt 裡 `## 第 {N} 回` 的 N **根本沒接線**（調查確認沒人傳入）。跨章連續性目前**只靠 MemWal
   三因子召回碰運氣**，沒有 showrunner/arc 記憶（NARRATIVE_AGENTS N7 未建）。
   → **每章是孤島，湊不成一本書。**

**實驗證據（見 `outputs/`）**：

| Run | 材料 | Prompt | 結果 |
|---|---|---|---|
| **A1** | thin（現況） | A（現況） | 站陰影裡→還站陰影裡。**純觀察，可有可無**（重現你的問題） |
| **A2** | rich（增補） | A（現況） | 有轉折了，但「八年讓位」被「克制/不總結」規則壓成一帶而過，**啟下鉤子被擋掉** |
| **B1** | rich | B（重設計） | 承上+推進+啟下+揭一角私帳，**處境真的變了，抽掉書就破**（達標） |

## 二、成功的多視角作品怎麼做的（對照你的系統缺什麼）

| 手法（來源） | 它的要求 | 你的系統現況 | 缺口 |
|---|---|---|---|
| **Swain Scene/Sequel**（每個單元 = 目標→衝突→**災難/轉折**；接 反應→兩難→**決定**） | 每一節結束時**故事狀態必須改變**（cause & effect，不能 episodic） | POV 材料無「目標/災難/決定」結構；事件多不結算 | **材料缺戲劇結構**；事件缺結算 |
| **GRRM 多 POV** | 每個 POV 角色有**辨識度極高的聲口**；每章只透過此人有限視角，且**每章推進主線** | 有 roleHint 聲口、有限視角做到了；但「每章推進主線」沒有 | **缺「每章必須推進」的約束** |
| **戲劇性反諷 / 多 POV 不重複**（每個 POV 掌握**不同資訊**，沒有人握有全部真相） | 角色版之間**靠資訊差**互補，不是同場景複述 | 群像/POV 目前是「同事件不同角度」，但**沒有刻意的資訊差/私帳** | **缺 per-character「私帳」**（只有他知道的 why） |
| **AI 長篇：DOC / Re3 / Dramatron**（plan-then-write：先生**分層詳細大綱**，再逐章生成並**受大綱約束**；DOC 比 Re3 在劇情連貫性 +22.5%） | 有一個**持久化的書級大綱**控制每章往哪走 | 無 arc/大綱物件；連續性靠記憶召回碰運氣 | **缺 showrunner/大綱層**（N7） |

**一句話**：成功作品的共同點是「**每一個敘事單元都讓故事狀態改變，且改變被一個書級結構記住**」。
你的系統三樣都缺：單元無戲劇結構、prompt 禁止狀態改變、無書級結構記住改變。

來源：
- Swain scene/sequel：<https://www.septembercfawkes.com/2021/09/scene-structure-according-to-dwight-v.html> · <https://en.wikipedia.org/wiki/Scene_and_sequel>
- GRRM 多 POV：<https://theskillfulminds.in/2025/02/27/how-to-structure-a-series-like-george-r-r-martin-and-develop-deep-pov-writing/>
- 多 POV 資訊差/反諷：<https://www.savannahgilbo.com/blog/multi-pov-pros-and-cons> · <https://rivereditor.com/guides/how-to-write-multiple-pov-novel-2026>
- AI 長篇 plan-then-write：DOC <https://aclanthology.org/2023.acl-long.190.pdf> · 動態分層大綱 <https://arxiv.org/html/2412.13575v1>

## 三、雙書分類設計（梨園版 vs 角色版各自成書）

兩本書是**同一條時間軸的兩種切法**，分工互補，不是同一份東西換皮：

```
                時間軸（事件 1 → 事件 2 → 事件 3 → …）
   梨園版（橫切）  ─────────────────────────────────►  一個事件一回，多視角並置
   角色·柳生春版（縱切） ●────────●────────●           只取柳生春出場的事件，串成他一個人的成長線
   角色·顧驚鴻版（縱切） ●────────●────────●           只取顧驚鴻出場的事件，串成他一個人的沉淪線
```

| | **梨園版（事件合本）** | **角色版（每角一本）** |
|---|---|---|
| 切法 | 橫切：一個事件 = 一回 | 縱切：一個人跨多事件 = 一本 |
| 視角 | 多主觀並置（羅生門） | 單一限定視角 |
| 回答的問題 | **發生了什麼**、各人如何**不同** | **為什麼**、這個人**如何變成這樣** |
| 揭不揭私帳 | **不揭**（留懸念當 CTA） | **揭**（每回揭一角童年/暗情/傷口） |
| 連續性的骨 | saga 事件時間軸（第 N 回 = 第 N 個結算事件） | 角色出場序（第 N 回 = 他第 N 次出場） |
| 書級主問 | 春雪社能不能在上海守住「戲比天大」 | 柳生春能不能不再怕被別開眼 / 顧驚鴻能不能放下那一眼 |
| 存取/商業 | 公開漏斗（發現層） | 訂閱深度（「追這個角色」） |
| 對應現有產物 | `event-chapter-compiler`（合本） | 現在的單 POV「原料」——**需升級成連續的角色章回** |

**關鍵洞察**：你現在的痛點之一是「角色版只是 POV 原料的堆疊」。修法是**角色版也要有自己的書級結構**
（自己的回數、自己的主問、自己的承上啟下），而**它與群像版的差異化來源 = 私帳（資訊差）**：
群像版看得到「柳生春沒別眼」，只有柳生春版告訴你「因為七歲那年母親被人別開眼」。這條資訊差
就是訂閱的理由，也是「原來如此」的來源。

## 四、IA 重設計（讓讀者看到「結果」不是「材料」）

現況問題（你說的「一堆材料」）：dossier 把 `ChainPovSection` 當「POV 原料」一段段列出，
feed 也曾把單 POV 當頂層條目。**「原料」這個框架本身就是 bug——讀者不讀原料。**

### 原則：每個 surface 只暴露「一本書的入口」，不暴露中間產物

```
/feed（發現層 = 梨園版這本書的入口）
  └─ 公報（每日頭條，免費漏斗）
  └─ 章回（= 梨園版，一回一事件，按回數連續排）   ← 主閱讀面
        每張卡：第 N 回 · 回目對句 · 在場角色 chips · 劇照 cover · 「讀 N 個視角」CTA
  └─ 影像（劇照畫冊 / clip）
     ⛔ 單 POV 不在 feed 頂層出現

/dossier?id=角色（= 那個角色那本書的入口）
  └─ 「{角色}的故事」= 角色版連續章回（有序、有回數、有「序」）   ← 升級重點
        不再叫「POV 原料」；叫「第 N 章」，像在讀一本人物傳
  └─ 「{角色}參與的回」= 連到梨園版對應回（橫向跳轉）
  └─ （刪掉）裸露的「同場群像 / mock 視角」並列三段 → 收斂成上面兩入口

事件頁 /feed/event/[id]（= 轉化頁，兩本書的交叉口）
  └─ 客觀骨架（公開）
  └─ 梨園版這一回（公開漏斗，刻意不揭私帳）
  └─ 「換個人重看這一刻」= 各角色版該回（gated）← 私帳在這裡，付費深度
```

落點（對照 CONTENT_PIPELINE.md §8 已有的 IA，差異是**把「原料」改成「書」**）：
- `components/dossier/tabs/ChaptersTab.tsx`：「{角色}視角·鏈上 POV（原料）」→ 改成「{角色}的故事 · 第 N 章」，
  加回數與「序」（角色版主問），視覺上是一本書不是一個 feed。
- `/feed` 章回 mode 的 `CutList`：卡片加**回數**（見 §五-4）與「讀 N 個視角」CTA。
- 移除任何把單 POV 當頂層可讀條目的入口（POV 只從「事件頁的視角切換」或「角色版章回」進入）。

## 五、落地建議（對應主代碼，按投資報酬排序）

> 全部可在主分支照做；本實驗已先驗證方向。建議順序：1 → 2 → 4 →（demo 後）3、5。

### 1.（最高 ROI）材料層：把 storylet 事件升級成「有結算的戲劇單元」
- **根因**：EVENT_LIFECYCLE.md §1 已診斷——storylet 永不結算 → 沒有轉折/代價可寫。
  **Phase 2 event spine 程式碼已落、flag-gate（`eventSpine` 預設關）、未在真鏈驗。**
- **動作**：在有 sui/錢包的 session 照 EVENT_LIFECYCLE.md §5 runbook 驗 `eventSpine`，把它打開。
  事件結算後，`triggerNarrative` 才會帶 verdict/outcome（tick-loop.ts 已有 verdict 注入邏輯）。
- 沒有這層，下面的 prompt 改進會餓肚子（A2 已比 A1 好，但前提是材料有結構）。

### 2. 材料層：POV 材料補「戲劇結構 + 私帳」兩個欄位
在 `PovPromptInput`（character-worker/prompt.ts）加：
- `beatStructure?: { stakes; turn; outcome; cost }`——從結算事件的 outcome 派生（賭注=爭的資源、
  轉折=verdict、結算=資源易手、代價=輸家失去什麼）。這把現有的鏈上事實**翻譯成戲劇語言**。
- `privateLedger?: string`——**只給這個角色一條只有他知道的 why**（資訊差 = 角色版的差異化來源）。
  來源：角色的 genesis memory / reflection 裡蒸餾一條「軸心傷口/慾望」，每回揭一角。
- 對應 `materials/event-01-rich.md` 的 B、C 兩節就是這兩個欄位的形狀。

### 3. Prompt 層：把「禁止劇情」改成「劇情必須來自材料」
- 用 `variants/prompt-B-redesigned.md` 取代現況 POV system prompt 的取向：
  保留所有**不捏造**鐵則（這些是對的），但加上**承上/推進/啟下/揭一角私帳**四項硬要求，
  並明確區分「捏造正典（禁）」vs「寫材料給的轉折（必須）」。
- 注意：**這一步單獨做會回退**（沒有材料層 1、2，prompt 要求推進但無料可推 → LLM 會傾向捏造，
  正是現況 prompt 當初要防的）。**所以 prompt 改必須跟在材料改之後。**

### 4. 連續性層：接「回數 N」+ 最小 showrunner 記憶
- **回數（小修，立即可做）**：合本 compiler 的 `## 第 {N} 回` 現在 N 沒接。
  最簡版＝per-saga 維護「已結算事件計數」當梨園版回數；per-character 維護「出場計數」當角色版回數。
  存哪：先 process-local，跟 economy shadow 一樣，後續移 relayer KV。
- **最小 showrunner（中等，demo 後）**：per-book 持久化一個三行大綱
  （主問 / 上一回結在哪 / 本回應推進什麼），餵進 POV 與合本 prompt 的「承上啟下」。
  這就是 DOC 的 detailed-outline-control 的輕量版，是 NARRATIVE_AGENTS N7 的 MVP。
  沒有它，連續性永遠靠 MemWal 召回碰運氣。

### 5. IA：dossier「POV 原料」→「角色版的書」（見 §四）
- 純前端，低風險，但**等材料/prompt 改完、角色版真的連貫了再做**，否則只是把孤島重新包裝。

## 六、怎麼在有 key 的環境真跑這個實驗

本資料夾已備好可直接餵真模型的素材：
- 材料：`materials/event-01-thin.md`（現況）vs `materials/event-01-rich.md`（增補）
- prompt：`variants/prompt-A-current.md` vs `variants/prompt-B-redesigned.md`
- 我的對照樣本：`outputs/run-*.md`（當人類盲評的基準）

**建議流程**：用 cheap-tier（GLM）跑 A1/A2/B1 三格 × 各 3 seed，找 3 個不知情的人盲評
「這一章抽掉，書會不會破？」（破=有推進，不破=可有可無）。若 B1 顯著勝出，就照 §五 1→2→3 落地。
也可把 `outputs/` 我的樣本直接拿給 owner 做眼檢，先定方向再花 key。
