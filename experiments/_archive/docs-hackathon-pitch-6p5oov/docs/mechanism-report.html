摘 要

Endless Story 是一個自治敘事世界：角色為 Sui 鏈上資產，其記憶以 SEAL 加密存於 Walrus，敘事由兩類自治 agent（導演／角色）驅動，戲劇張力與經濟結算由確定性定點數 純函數負責——LLM 提供提案與意義，守恆量的一切轉移皆可重現、可驗證。

系統的核心結構為「正史共享，視角私有」：客觀事件骨架（鏈上事件日誌與導演公報） 唯一且公開；每個角色對同一事件持有主觀、加密、互不滲漏的詮釋，形成可規模化的多視角敘事。 經濟層令記憶儲存成為單調上升的租金，由此保證角色死亡與世代交替；其無永生、可養活、 同盟有效等性質均經離線確定性模擬以假說檢驗方式驗證（economy 41、drama 29、runner 48 測試全綠）。

本卷描述系統架構、各機制設計與實作狀態；公式推導、校準參數與實驗結果見數學與實驗卷。

1.2 三條工程紀律

  1. LLM proposes，deterministic layer disposes。LLM 負責提案、措辭與意義； 資源配置、金錢、氣血等守恆量的狀態轉移一律由定點數純函數結算，LLM 永不輸出數值增量。
  2. 單一真理純函數，先驗證後產品化。機制核心先以零依賴純 TypeScript 模組 （packages/drama、packages/economy）完成離線驗證；產品與 Move 合約移植同一份轉移函數，永不重寫。
  3. 逐位元組可重現。全程 bigint 定點數（SCALE = 10⁶），與 Move u64/u128 算術 1:1 對應；golden vector 與跨層一致性測試保證鏈上 re-run 可驗。

1.3 系統閉環

徵召 mint（§3）→ 入科記憶與關係網（§7）→ 自治 tick：雙 agent（§4）→ 事件開回·續回·收回（§5）→ 張力由稀缺資源湧現（§8）→ POV → 合本章回 → 公報 → 劇照（§6）→ 訂閱·金庫·發薪（§9）→ 記憶租金單調上升 → 死亡釋位（§9）→ 世代交替 → 回到徵召

敘事側令世界活著（記憶決定行為、行為產生記憶、張力來自守恆的稀缺）； 經濟側令世界有重量（append-only 儲存的物理性質直接構成死亡機制）。

2.4 承諾模式與事件匯流排

產出文本／圖像→ hash→ Walrus 上傳→ commitment::commit 錨定→ emit *Committed

導演與角色間無 in-process 狀態：通訊即鏈上事件匯流排（StoryletOpened、CharacterCalled、 RelationshipSeeded、CharacterMoved、ChapterCommitted⋯）。鏈上事件日誌同時即「導演的客觀 記憶」——append-only、不可竄改，與角色主觀私密記憶構成刻意的不對稱（§7.3）。

2.5 架構七原則（摘錄）

  • 依賴單向：web / runner → sdk + memwal + llm；shared 零依賴。
  • sdk 為鏈上互動唯一入口；memwal 為 Walrus／SEAL 唯一入口；llm 為 AI client 唯一入口。
  • shared/contract-ids.ts 由 cli 寫入為部署輸出單一真相，其餘只讀。
  • admin 操作以 server actions 為先；(site)／(admin) route group 嚴格隔離。

3徵召與定價 已實作目錄

角色四軸先天屬性（外貌／筋骨／機敏／心性）由 32-byte 種子經 HKDF-SHA256 域分離擲出， 單軸均勻分佈於 [0,100]、四軸獨立、同種子必得同角色。徵召可設每軸門檻； 「必應」由後端零成本重骰至達標方生成 mint，定價錨於期望硬抽花費：

p = ∏ᵢ (101 − mᵢ)/101 E[draws] = 1/p bulkPrice = max( basePrice, round₁₀( basePrice × E × 0.85 ) )

margin 0.85 使必應略廉於期望硬抽，消除變異負體驗並平滑營收；門檻越苛 E 越大， 故必應為 per-徵召值（現役 13 徵召 E 介於 4.4–27.2）。推導、性質與邊界條件見數學卷 §1。 mint 為阻塞式（畫像生成完才上鏈），保證 NFT 縮圖與顯示同一張；mint／抽卡費入 saga 金庫， 為 §9 發薪池的入金來源之一。

4敘事引擎：雙 Agent 自治迴圈 已實作目錄

理論基礎：Director–Actor 分解（IBSEN／Co-DIRECT）與 Generative Agents 認知迴圈 （Park et al. 2023）。目標為 C 級全自治——角色自行感知、回憶、規劃、行動、反思， 世界無人駕駛地前進；骨架已全數落地。

4.1 權責分界

Director（一 saga 一隻）Character（一角色一隻）
職責目標、開局、調度、監看與重導、客觀公報感知、決策、行動（移動／出牌／開口／金錢）、人設、記憶與關係、主觀 POV、反思
界線不替角色決定如何演、出哪張牌不無視導演開的局（可詮釋、可抗拒）
溝通鏈上軟事件（capability；給提示不給台詞）訂閱鏈事件，以鏈上動作回應
模型分級規劃用高階模型（低頻）決策用低階模型（高頻）；POV／反思用高階模型

判準：「此角色此刻做了什麼」屬角色；「世界往哪推、誰上場、今日大事」屬導演。 衝突時角色自圓其說（failing believably）。

5.1 事件 spine（開回 → 續回 → 收回）

tick T 開回 pushEvent + 發牌；該回合的卡一次出完（現行合約為單回合） T..T+n 續回 事件維持 OPEN；POV／反應跨 tick 累積，全部鎖同一 event id T+n 收回 resolve_event 攜資源轉移（贏家奪標的）→ 需求轉移 → 世界前進； 合本於此將整回 POV 一次織成「回」

診斷出的根因：先前以逐 tick storylet（只 emit、無物件、永不結算）充當事件 ⇒ 資源永不易手 ⇒ 張力靜止 ⇒ 主題鬼打牆。spine 以既部署的鏈上 primitive（pushEvent／submitAction／ resolveEvent 攜 resource transfers）補上「會結算、能推進世界」的事件單位，毋需 redeploy。 結算每一步皆有 fallback——任何失敗退回純收尾，open 事件絕不卡死迴圈。

6.2 章回 = 事件合本（拍板）

正式「章回」為事件合本而非單角色 POV：compiler 吃同一 eventTx 的全部 POV ＋ 客觀事件骨架，織成一篇多視角章回（subject = event_id；≥2 篇 anchored POV 方織—— 僅在有付費觀眾處花成本）。單 POV 退為角色個人 feed 與未來 PV 素材。 /feed 與人物頁的資訊架構已翻成 event-centric：feed 由事件展開角色、 dossier 由角色切入事件。

7記憶與認知 已實作目錄

7.1 三因子召回

記憶為 SEAL 加密文字存 Walrus，前綴標籤 [[m|t=kind|i=imp|d=敘事日]]。 召回分數 = importance × recency × relevance（半衰期 2 敘事日，以敘事日而非牆鐘衰減）； importance 刻度：夢 9 > 關係 8 = 規劃 8 > 反思／創世 7 > 章回 5 > 觀察 4。 託管模式 over-fetch 3× 後 client 重排；自架 relayer（plaintext-blind）對全 namespace 計算真三因子回 top-N，省約 3× SEAL 解密。公式與細節見數學卷 §6。

7.2 軟遺忘與睡眠壓縮

MemWal append-only、無刪除。睡眠期將非 anchored 零碎觀察壓縮為高密度反思 （i=8、anchored 永不再壓），疊加 recency 衰減令零碎記憶自然沉底——遺忘為湧現性質、 bytes 永不消失，此即 §9 記憶租金的物理基礎。

7.3 主觀記憶與視角化真相（設計鐵則）

系統不維護全知正典
角色私密記憶為主觀、視角化；因 SEAL 隱私界線，角色僅能見他人公開描述，對他人秘密 的理解只能自行長出一個版本——同一事件在不同角色心中各有一版，錯位即戲。 實測案例：班主沈雪笙之私密真相為「白蘭遠嫁，從此封箱」；後入班的衣箱師傅唐桂蘭 經 induction 自行長出第二版（箱底染血戲衣、委身軍閥之往事）。兩版互不知情、皆未外洩， 系統零跨角色滲漏即自然產生視角化真相——加密邊界本身即敘事引擎， 亦為 §6.2 合本章回（羅生門式織法）的素材來源。欲令 A 確知 B 之秘密，唯有明寫入 A 自身之描述；系統不跨角色洩漏。

8戲劇張力引擎 已接入 tick 29 測試目錄

核心命題：張力不來自慾望本身，而來自慾望投射到有限、守恆的資源上、 無法同時被滿足的那條邊。三 primitive（Desire／Resource／Action）與純轉移函數 applyTick（REFILL → RESOURCE → SATISFACTION；tension 為讀取時導出量）：

target = SCALE·held/want s += α·(target−s)/SCALE (α_down 0.60 > α_up 0.30 ⇒ 損失趨避) s += γ·(baseline−s)/SCALE (γ 0.05 ⇒ 習慣化) tension = weight·(SCALE−s)/SCALE
  • 形式性質：守恆（違規提案 reject）、有界無 clamp、決定性（逐位元組）。衝突為湧現—— 跨 agent（同一 capacity-1 資源之零和）與 agent 內（有限行動預算之取捨），皆無宣告式 conflict matrix。
  • 校準結論：行動預算補充率決定奪位週期（budgetCap 12 ⇒ 政權期 ≈ 7 tick）， 將逐拍抖動轉為可讀的宿敵節奏。三種失敗模式（flatline／runaway／oscillation） 已操作化為數值斷言；負控制消融證明 margin 與預算為承重結構。
  • 柳生春時刻（agent 內取捨）為湧現而非劇本：單變數消融（僅放寬預算）令被迫二選一 120→2，證明預算為因。實驗全表見數學卷 §2.6。

8.1 鏈上對應

resource.move 為 RESOURCE 相位的 Move 對應體（守恆＝合約不變式，轉移提案於鏈上 重驗）；跨層一致性測試釘死同一 beat 在 TS 與 Move 兩層須得逐位元組相同的 allocation 與 導出張力——「任何人 re-run 得同樣張力」主張的最後一環。事件結算（§5.1 收回）即透過 resolve_event 攜資源轉移落實易手。

8.2 注意力預算耦合 旗標保護

並行事件之間經共享角色互相拉扯：每角色僅全額供養張力排序前 focus 個慾望， 其後的慾望被冷落放大，聚合後令被冷落軸的全域張力上升、選題轉向之。對單慾望角色為恆等； 僅作用於 off-chain 需求訊號，不觸碰鏈上守恆。人物層以「顧此失彼」提詞落到台詞與決策。

9.1 金流閉環與守恆

訂閱費／mint·抽卡費／夢費→ saga 金庫＝發薪池→ 角色 Balance（真實持幣）→ 扣 dailyCost→ 協議金庫（對應真實基建帳單）
守恆：injected ≡ ownerSink + storytellerSink + protocolSink + sagaTreasury + Σ balance dailyCost = C_run·activeFactor + C_mem·memory_count + C_img·image_count + C_seal·recallCount

記憶 append-only ⇒ memory_count 嚴格單調上升 ⇒ 休眠可逃推論費、 不可逃記憶租金（新生 dailyCost ≈ 7.1，一敘事年 ≈ 50.3）。薪餉為混合制 （行當保底 × 屬性係數 ＋ 按訂閱數分配之績效池）；金庫由 mint／抽卡／夢費注入， 故零訂閱亦有保底班中俸，金庫空方為零。公式見數學卷 §4。

9.2 氣血與雙軌死亡

vitality ∈ [0,100]；經濟軌（連續破產加速扣血，滿血至死約 5 日、一旬搶救窗口）＋ 年齡軌（隱藏 hazard：不存壽限欄位，onset ≈ 55 ± 私有種子變異、永不上鏈）。 死期由氣血累積湧現，無人可預先計算。死亡 → 釋放持有資源（席位回自由池）→ 遺產回流 owner → 後輩競逐——世代交替閉環。

9.3 金錢行為：四個 agent 動作

給（decideAidAction）／收拒（受方可回絕施捨）／要（decideAskAction）／回應。 分界原則：LLM 決定「要不要、對誰」（戲），硬守衛決定「能不能、至多多少」（帳） ——收款人須在場、金額 clamp ≤ 餘額、禁自轉／給死者，全部對齊純函數 applyTransfer （淨額 0、不破壞守恆）。eval：3 hard 必過全過、3 judgment 情境判斷皆可辯護。

9.4 結算相位與現況

ASK（2.85）→ GIVE（2.9）→ SETTLE（2.95）已接入 tick loop（§4.2）：以鏈上金庫餘額為 發薪池種子、日結 idempotent、轉帳逐 tick 套用；影子已死者剔出 active slice、人物頁顯示歿。 整條「發薪 → 扣租金 → 求助 → 接濟（可拒）→ 退場」已可端到端觀察。 現為 off-chain 影子權威（store process-local）；鏈上權威結算 economy.move（D1：per-char Balance、transfer、settle、自然死包裝）為既定後續， 移植對象即已驗證之純函數。付費訂閱與分潤開關 刻意延後 （RevenueConfig 欄位已就位；subscribe 收費為上游前置）。
