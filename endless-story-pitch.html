The Problem  ·  真正的問題

今天的 AI 角色，記不住任何事

LLM 本質是無狀態的。關掉對話，這個「角色」就死了——它不記得你、不記得自己做過什麼、也不會成長。塞進 context window 的，只是當下的短期記憶。

SESSION 1
「我是雪庵，恨過、也愛過。」
「我答應過師父守住戲班。」
「我與沈郎結了梁子。」
⟶
session 結束
SESSION 2
「你好，請問我是誰？▌」
— 一切從零開始。記憶歸零。

角色要能「活著」，記憶必須獨立於模型、獨立於平台而存在——而且這份記憶，應該被某個人真正擁有。

The Insight  ·  我們的切入

把「記憶」做成一種資產

不是存進某個公司的資料庫，而是寫進去中心化儲存、由密碼學保護、由你持有金鑰。記憶因此有了四個過去 AI 角色沒有的性質：

持久

跨 session、跨模型存在。換掉底層 LLM，角色依然記得自己是誰。

可擁有

記憶的解密金鑰綁定鏈上 Cap。持有者＝真正的 IP 擁有者。

可驗證

每段記憶 hash 上鏈錨定，誰、何時、寫了什麼，不可竄改。

可變現

章回訂閱、衍生作品、影像 IP——記憶資產直接接上分潤。

System Architecture  ·  系統架構 · 依賴單向

四層 monorepo，每件事只有一個入口

packages/ · dependency graph (single-direction ↓)

鐵律：上層不准自己 new SuiClient()、不准直接打 Walrus/AI API。鏈、儲存、模型三類外部相依，各自封裝在單一邊界後。

★ Core · MemWal × Walrus × Seal  ·  記憶讀寫時序

一段記憶，怎麼加密上鏈、又怎麼解密召回

sequence · write (remember) ─── read (recall)

關鍵：明文只在 client 端存在。Seal 的解密授權綁定角色的 ControlCap / OwnerCap——撤銷 Cap＝斷掉記憶存取。

Memory Engine  ·  三因子召回

不是 KV 查詢，是會遺忘的語意檢索

recall pipeline · over-fetch ×3 → score → rerank → top-K
importance weights · by kind

軟遺忘（append-only，無刪除）：角色「睡一覺」時，把零碎 observation 壓縮成 1–2 條高密度 reflection（i=8、標記 a=1 不再被壓），靠權重＋衰減讓瑣事自然沉底—— 記憶不爆炸、角色不失憶。

AI Harness · Runner  ·  自治迴圈（輔）

角色每個 tick 的狀態機

character-agent · perceive→…→reflect (chain-first)

決策 = 鏈上 primitive

event::submit_action（出牌）
scene::move_character（移動）

產出 = 簽名上鏈

POV → hash → Walrus → commitment::commit → emit

導演 / 角色分工

導演定目標、發軟事件；角色自己詮釋、回應。靠鏈上事件溝通，不互相寫死。

Ownership  ·  能力金鑰 · 存取控制

公開的世界，私密的靈魂

cap-based access · seal_approve gating

同一套內容、兩種存取：世界的客觀公報公開當門面與流量；角色的主觀章回私密，client 端驗持有者才解密。

角色 NFT → 影像 IP → 記憶 IP → 章回訂閱分潤

非讀者只拿得到鏈上 anchor（可驗證），拿不到 Walrus 明文——這是真正的「擁有」，不是平台施捨的權限。
