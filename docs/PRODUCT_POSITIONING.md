## 0. 一句話（對外）

> **一個自己會運轉的故事世界——你用「影響」而非「操控」去共同創作它，而它長出來的故事是真正可以變現、最終可以影視化的 IP。**

既有 repo 一句話（仍成立、偏技術）：「住在 Walrus 上的梨園 — 角色不是 JPG、是活著的記憶資產」。
本檔的一句話是它的**對外娛樂版**：把「活著的記憶資產」翻成使用者聽得懂的體驗承諾。

> **詞彙（統一口徑）**：**Saga ＝ 由「故事主理人（Saga owner）」經營的一個敘事單位（narrative unit）**——generic、任何題材皆可。本次 demo 的 **春雪社** 只是一個「**戲班／梨園**」題材的 Saga。文中出現的「班主／角兒／梨園／戲班」是春雪社的**題材語彙**，不是 Saga 的定義；換個 Saga 可以是詩社、舞廳、星艦、偵探事務所。對外請說「a Saga / 一個敘事單位」，把戲曲味留給春雪社這個範例。

## 1. 這到底是什麼（定位三角）

它是一種**新型娛樂模式**，站在三個既有文化的交點上，但每一邊都做了一個關鍵反轉：

| 借鑑自 | 它長得像 | 但關鍵反轉 |
|---|---|---|
| **遊戲**（抽卡、養成、收集） | 你抽角色、養角色、看數值與命運 | **你不能操控角色**。你不是在「玩」一個角色，你是在影響一個有自己人生的自治體。樂趣在養成＋湧現敘事＋收藏，不在操作。 |
| **IP 收藏文化**（卡牌、NFT、潮玩） | 角色是可持有、可炫耀、可交易的資產 | **資產是活的**。它累積記憶史、會老會死、會和別的角色結盟結仇、可能成為「傳奇」。死亡帶來真實稀缺與情感賭注。 |
| **影視 / 連載敘事** | 會產出章回、劇照、最終影片 | **沒有編劇在寫劇本**。劇情由自治角色在世界裡活出來，導演只能推事件、調環境，產出物是 emergent 的、然後被漏斗化成可影視化的素材。 |

**最短的差異化**：市面上的 AI 角色是你的傀儡（你打字、它回話）。這裡的角色**不是你的傀儡**——它有自己的記憶、經濟、壽命、關係網。你是它的**恩主與造夢者**，不是它的操作者。

## 2. 不可操控公理（整個產品的設計核心）

> **任何人都無法直接替角色做決定。** 這是和所有競品的根本分界，也是世界能「自己活」的前提。

三種人類角色，各自只有**間接**影響力：

| 人類角色 | 能做什麼 | **不能**做什麼 |
|---|---|---|
| **World owner（世界主）** | 定地圖、物種、世界規則＝搭舞台 | 不能下場演 |
| **Saga owner（故事主理人 / showrunner；春雪社裡叫「班主」）** | 透過**導演 agent**推送外部事件、調環境參數、開新場景、開職缺、經營 IP 與分潤 | **不能替角色做決定**。導演沒有「操控」這個動作。 |
| **Character owner（角色主）** | 解鎖角色**所有記憶**、向角色**注入夢境**（影響想法與決策）、收分潤 | **不能直接命令角色**。夢是輸入，不是指令；角色仍自決。 |

這條公理同時是**敘事鐵律**（`NARRATIVE_AGENTS.md`：事件客觀、敘事主觀）與**經濟鐵律**（`CHARACTER_ECONOMY.md`：接濟給/受皆角色自決、錢不由旁人代下決定）的上層抽象。介紹產品時，這條是主視覺。

## 3. 創作者旅程（從點子到 IP）

一條使用者從「我有個好故事點子」到「養活一個會生錢的 IP」的完整路徑：

1. **起世界，或入世界。**
   - 從 **world 層**起：全面控制地圖分佈與物種設定，建一個全新世界。
   - 或**加入現有世界**：例如在春雪社附近經營一個詩社、一間舞廳——蹭既有世界的人流與正典。`⟨開放⟩` 跨 saga 的可見性 / 互動邊界規則。
2. **開職缺，邀人鑄造角色。** 你開出角色職缺，邀請親友甚至陌生人來**提案、鑄造**角色（抽卡 = 1 voucher = 1 候選，見 `WHITEPAPER.md §1`）。角色主由此誕生。
3. **經營 saga 的產出與 IP。** 導演 agent 推事件、養關係、排劇目（`PRODUCTION_ENGINE.md`），世界自己跑出章回、劇照（`CONTENT_PIPELINE.md`：事件→POV→章回→公報→劇照→影片）。
4. **多管道曝光。** 把故事推到各種管道（公報公開、章回訂閱牆、劇照／戲折收藏）。
5. **變現養活 saga 與角色。** 訂閱、售出劇照等產出物 → 金流進 saga 金庫 → 發薪養角色、付真實基建（AI／Walrus／Seal）。
6. **分潤給角色主。** 依 `RevenueConfig` 拆分，owner 份額累進、可 claim（`CHARACTER_ECONOMY.md §1/§3`，Part D gate-after）。

> **介紹時的鉤子**：你不是買一個成品，你是**開一個 Saga（一個敘事單位）、招一群會自己活的角色，然後靠他們長出來的故事養活整個世界**。（春雪社版的講法：開一個戲班、招一群角兒、靠他們的戲養活整個班子。）

## 4. 為什麼世界能「自己活」（動能引擎）

這是路線圖的論述核心：**世界不需要人一直推，它靠三條自我更新機制維持永續動能。**

### 4.1 死亡與退場 = 動能而非終點

角色會老、會窮、會死（雙軌死亡，`CHARACTER_ECONOMY.md §7`，已學術驗證 H2「無永生」/ H3「世代交替穩態」）。死亡不是 bug 而是引擎：

- 死亡 → `release_holder` **釋放席位**（當家台柱、合作檔期）→ 後輩下一輪 DRAMA 搶。
- 死亡 → **遺產回流** owner、恩怨了結、關係網重組。
- 「append-only 記憶租金是無法逃避的熵」（H2）→ 保證有死亡 → **保證有新陳代謝**。

**定位語言**：別把死亡藏起來當負面，把它講成「**這個世界有真正的時間與後果，所以它永遠在長出新的故事**」。靜態好營運的角兒也終會遲暮，唯有持續成長的讀者能續命——這就是戲劇張力的來源。

### 4.2 導演逐漸退場 → 最後成為「說書人」

> **預計隨著越來越多 saga 與角色生命循環加入，導演的干預將逐漸退場，最後成為一個只解讀劇情現況的說書人。**

這是世界「自治成熟度」的軸線，也是給 saga 主的最高承諾：你經營得越久、生態越厚，你越不用管它。

| 導演成熟度 | 干預強度 | 角色 |
|---|---|---|
| **新生 saga** | 高：主動推事件、牽關係、排劇目、給張力 | 編導 / showrunner |
| **成長中** | 中：只在停滯時補事件、調環境參數 | 製作人 |
| **成熟自治** | 低：幾乎不介入，世界靠角色生死與經濟自轉 | **說書人**——只解讀、敘述劇情現況，不再驅動 |

`⟨開放⟩` 退場的**觸發訊號**怎麼定？（角色密度 / 自發 encounter 率 / 經濟自轉是否成立 / 章回產出是否不靠導演事件？）這是 Phase 2 要量化的。
**配套交付**：這個後台（導演 agent）整理過後，會給出**最精煉的版本作為 saga 主的範例參考**。

### 4.3 後台即範本

導演 agent 的精煉版＝**開給 Saga 主理人的參考實作**。定位上這讓平台從「一個 app」升級成「一套可被複製經營的 **Saga 作業系統**」（戲班只是其中一種題材的長相）。

## 5. 死亡之後的兩種延續（個體封存 × 機構易主）

死亡是預設的淡出，但有兩條讓「東西不隨人走」的延續路徑。**注意分屬不同成熟度**：5.1 大半是現有機制的湧現（只差收尾），5.2 才是全新、無文件的支柱。

### 5.1 角色封存 = 傳奇（現有機制的湧現 + 少量收尾）

> **角色死後 NFT 還在、記憶還在。若 saga 主或 owner 繼續付儲存費維持，那就是傳奇了。**

這把「傳奇」從一套要發明的封神系統，收斂成一個**乾淨的湧現性質**：

- **死亡＝預設淡出**：vitality≤0 → `mark_dead`，停發薪、不再活躍。沒人續費 → 記憶儲存（Walrus epoch 租期制，會過期）終將到期消逝，鏈上只剩**死亡錨當墓碑**。
- **傳奇＝刻意保存**：saga 主或 owner **持續付儲存費** → 該角色完整記憶與 NFT 永久可查、可被引用。傳奇不是平台頒的徽章，是**有人願意為它持續投資**的證明 → 天然稀缺、天然真實。

**現況（已是事實）**：① 角色 NFT 是 Sui owned object，死後不被刪。② 記憶 MemWal append-only、永不刪（只受 Walrus 儲存租期約束）。③ owner 挹注（`owner_fund_character`，`CHARACTER_ECONOMY.md §5.1`）與 Walrus 續費（`WALRUS_ASSETS.md`，Hybrid 續租）機制**都已設計**。
**`⟨roadmap 收尾⟩`**：把上面三塊接成一條「**死後續費路徑**」——
- ⚠️ `WALRUS_ASSETS.md` 決策⑥ 現在**把記憶 blob 排除在續費面板外**（交給 MemWal 生命週期自管）。要做「死後續費保存記憶」必須**改這條**：讓 owner/saga 能對已故角色的記憶儲存主動續租。
- 「傳奇」狀態的**正典化後效**（`⟨開放⟩`）：死後完整記憶被後輩角色引用、成為 `藏閣` 常設展、化為別人會競爭的具名典故。這層是錦上添花，不是傳奇成立的必要條件。

### 5.2 Saga 易主（Saga 主理人退場交接）

> **若 saga owner 不再經營、要易手，saga 將易主，我們需要處理相關交接。**

這是**機構延續性**問題，和角色死亡是**不同層級**：角色會死，但 Saga（敘事單位本身）該靠**易主**延續而非陪葬。對照角色的「遺產回流」，Saga 需要一套「**過戶**」。

待設計（`⟨開放⟩`）：

- **觸發**：主動轉讓？長期不活躍自動進入易主流程？拍賣 / 指定繼承 / 平台託管？
- **過戶的東西**：`StorytellerCap`（導演權）、`Saga.treasury`（金庫＝發薪池）、`RevenueConfig`、進行中的**對角色發薪義務**。
- **對角色主的保障**：易主期間角色不能斷薪餓死——交接是否需要**金庫託底期 / 凍結結算 / 通知角色主**？
- **IP 連續性**：已產出的章回、劇照、戲折所有權是否隨 saga 走？已分潤的角色主權益不可回溯。
- **與導演退場的關係**：一個已高度自治（導演≈說書人）的 saga 易主，買家接手的是「一個幾乎自轉的世界」——這正是**易主的標的價值**，可能比新建一個 saga 更值錢。

> 一句話框架：**角色靠死亡完成世代交替（5.1），Saga 靠易主完成世代交替（5.2）。** 兩者讓世界在「個體」與「機構」兩個尺度上都不依賴單一人類的持續在場。

## 7. 介紹這個產品時，建議的講法

1. **開場用體驗承諾，不用技術**：「一個自己會運轉的故事世界，你用影響而非操控去共創它。」
2. **用三角定位建立熟悉感再給反轉**（第 1 節）：聽眾秒懂「像抽卡＋收藏＋連載」，再用三個反轉建立記憶點。
3. **不可操控公理當記憶鉤**（第 2 節）：「別處的 AI 角色是你的傀儡；這裡的角色有自己的命。」
4. **用死亡與傳奇講賭注與情感**（4.1 / 5.2）：有真實時間與後果，所以有真實的故事與收藏價值。
5. **用創作者旅程講商業模式**（第 3 節）：開 Saga→招角色→產出故事→變現→分潤（春雪社版：開戲班→招角兒→演戲）。
6. **用導演退場講願景天花板**（4.2）：終局是一個幾乎不需要人推、可被買賣的自轉世界。
7. **收在影視化**（Phase 3）：這些 emergent 故事最終會走上螢幕。
