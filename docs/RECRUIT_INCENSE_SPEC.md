# 徵角與香火 —— 「擁有而不操控」產品機制 Spec

> 產品判斷背景：擁有者鑄造角色（命名權＋seed 權，LLM 復核＋拓寫），以該角色
> POV 觀看世界，**不可操控**。已知死亡曲線＝旅かえる式三週退潮（純觀看衰減）；
> 破法＝Godville 式「**影響而不操控**」通道。本 spec 定義兩個 MVP 件：
> **復核座席**（正典守門）與**香火通道**（三條影響通道中最便宜的一條）。
> 家書（私密 scheduledEvents）與餽贈（spawn-object＋transfer）為二期，
> 機制全數現成、僅缺前端流。

## 0. 北極星指標

- **D7 回目開啟率**：鑄造後第 7 天仍打開每日 POV 回目推播的擁有者比例。
  旅かえる死在這條曲線；一切設計對它負責。
- **正典戲份守門**：量測器加「正典角色 beat 佔比」；用戶角色總戲份
  超過 ~35% 即停止該世界徵角（世界不被淹）。

## 1. 徵角（Recruitment）

### 1.1 後台（已有雛形：admin 設定徵求行當）
- 營運者按季開缺：`{ role: '武生', slots: 1, note: '班主嫌武戲太素' }`。
- 每 12 人班底世界，**每季用戶角色上限 3–5**（正典戲份守門硬上限）。
- 缺額即稀缺＝定價權；滿了開下一個戲班（多世界聯邦，成本另議）。

### 1.2 鑄造流（用戶）
1. 選缺 → 命名＋自寫背景 seed（外形/氣質/一樁往事/一個放不下）。
2. **復核座席**（見 §2）審＋拓寫 → 通過則入班（復活轉換器 #12 現成路徑：
   cast-state → world），拒絕則附一句班主口吻的理由（「本班不收帶槍的」）。
3. 擁有記錄先落資料庫（**不上鏈**；快照/fork 已保全所有權語意，
   鏈是日後「可攜可轉讓」的加值，不是 MVP 門檻）。

### 1.3 POV 視界（差異化核心）
- 擁有者**只經由角色所知**看世界：相識分寸（不認識＝「面生姑娘」）、
  幽物不可見、他人私密事件不可見。主觀知識物理＝天生戰爭迷霧。
- 每日一封 **POV 回目**推播（逐角色 POV 生成現成；#162 已去標題）。

## 2. 復核座席（decideRecruit）

沿 decideAdmit/decideLend 同一 pattern：純 leaf prompt＋cheap-tier client＋
嚴格 JSON＋敗退拒收。

- **輸入**：候選 `{name, 背景seed, 行當}`＋世界正典摘要（bible 節錄＋
  現有班底一覽＋本季開缺 note）。
- **三關**：
  1. **正典**：時代/世界觀相容（民國上海、無穿越西幻超能）；
  2. **文風**：名字與敘述合梨園語感（拒網文腔）；
  3. **安全**：拒擦邊/真人影射/仇恨內容。
- **輸出**：`{accept, 拓寫後seed?, 班主一句話}` — 拓寫把用戶的素材
  擴成引擎格式（description/secret/memories×3/skills×2，工作/居所由
  開缺決定），**保留用戶原句至少一句入 memories**（擁有感錨點）。
- 成本：每次鑄造 1–2 次 cheap 呼叫；拒絕免費重試 2 次。

## 3. 香火通道（influence, not control）

**擁有者每日至多一炷香**：替自己的角色，向觀音堂許一句話。

- **機制**（全現成）：
  - 寫入一條 **owner-prayer**（Prayer 結構，`source: 'owner'` 新欄），
    上願牆、進廟的場景內頁（#168 願籤切面）。
  - 對角色的效果＝**want 熱度微調**：香火指向的既有願 `heat += ε`
    （ε 小、日上限一次、不可指定行為——推「放不下」，不推「去做」）。
    無對應願則不生效（不能無中生願——自主權紅線）。
  - 角色**不知道**香火來自擁有者（世界內解釋：神明感應）；
    但夜裡自我省思可能「無端又想起那樁事」——percept 一行。
- **哲學紅線**：香火影響慾望強度，永不影響決策本身。決策仍全由
  decideMove/actBeat 的角色自主。
- **監控**：量測器加「香火→行動轉化率」（燒了香的願，7 拍內有無
  相關行動）——這是影響通道有效性的量化證據。

## 4. 二期（機制現成、缺前端）

- **家書**：擁有者寄信 → 私密 scheduledEvent（叩門拒門同渠道）→
  入記憶/percept；角色怎麼解讀是角色的事。頻率：每 3 日一封。
- **餽贈**：寄物（spawn-object 入隨身）或寄錢（transfer 入帳）；
  她轉贈給誰、拿去還誰的債，後果不由你。

## 5. MVP 順序與驗收

1. 復核座席（engine PR ×1）＋鑄造流（web）→ 內測鑄 5 角
2. 每日回目推播（POV 已有，缺推送管道）
3. 香火（engine PR ×1：owner-prayer＋heat nudge＋願牆標記）
4. **20 人付費 alpha → 量 D7 回目開啟率**；同時量正典戲份佔比與
   香火轉化率
5. D7 及格線（暫定 ≥40%）→ 才談家書/餽贈/多世界

## 6. 依賴與風險

- **品質前提**：觀看只有在世界好看時成立 → 三臂迭代（EXPERIMENT_ARMS）
  是本產品的前置閉環，不是旁支。
- **審核面**：復核座席是內容安全第一線；人工抽查前 100 個鑄造。
- **名額上限＝成長上限**：突破需多世界聯邦，屆時再算每世界 COGS。
